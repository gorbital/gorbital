# Upgrade notes

What changes for existing apps in each release, and what to do that `orb upgrade` can't do for you. How upgrades work: [ADR-0016](../adr/0016-scaffold-compatibility-and-upgrades.md) and [ADR-0050](../adr/0050-upgrades-and-adding-features.md); commands: [CLI reference](cli.md).

## Unreleased

Includes the fixes from the internal security review ([report](../security/2026-09-internal-review.md), [ADR-0053](../adr/0053-internal-security-review.md)) and the first v1.1 features: per-organisation settings ([ADR-0056](../adr/0056-per-organisation-settings.md)), idempotency keys ([ADR-0060](../adr/0060-idempotency-keys.md)), the email suppression list with Resend webhooks ([ADR-0062](../adr/0062-resend-webhooks-and-suppression-list.md)) and Prometheus metrics ([ADR-0063](../adr/0063-prometheus-metrics.md)); their rows start with **v1.1**. Rows are ordered by what you must do: first the changes to make **before deploying**, then changes your frontend or scripts may need, then what happens on its own.

### Before deploying

| Change | What to do |
|---|---|
| **`APP_ENV` is required** ([ADR-0020](../adr/0020-constructors-and-configuration.md)). Apps refuse to start without it instead of assuming development (HTTP-6) | Check every deployment sets `APP_ENV=production` (the generated Dockerfile does; custom images, systemd units and platform configs may not) and that `.env` has `APP_ENV=development`. `orb dev` sets development for you; plain `go run ./cmd/api` in a Minimal app needs `APP_ENV=development`. If your own tests call `LoadConfig`, set `APP_ENV` in them. `orb upgrade` brings `config.go` and `main.go`; `go run ./cmd/api openapi` needs no environment |
| **API docs are off in production by default** ([ADR-0027](../adr/0027-api-contract-and-docs.md)). `APP_DOCS_ENABLED` defaults to `false` when `APP_ENV=production`, and turning docs off now also stops serving `/openapi.json` and `/openapi.yaml` (HTTP-3) | To keep a public API reference in production, set `APP_DOCS_ENABLED=true`. `orb upgrade` brings the `routes.go` change (`openapi.WithoutSpecEndpoints()` when docs are off). Google and Apple web sign-ins without `return_to` land on `/docs`: pass `return_to` from your frontend |
| **`APP_CORS_ORIGINS` must use https in production** (HTTP-4) | Replace any `http://` origin in production with its https address; otherwise the app refuses to start and names it. Origins with user info, a path, query or fragment are refused in every environment (`httpx.CORS`) |
| **`APP_TRUSTED_PROXIES`** | Behind a load balancer or reverse proxy, **set it before deploying** to their CIDR ranges (such as `10.0.0.0/8`). Otherwise every client shares the balancer's per-IP budget, and logs and audit events show the balancer's address |
| **Clients can't choose their request ID or trace** ([ADR-0007](../adr/0007-observability.md), [ADR-0030](../adr/0030-context-and-correlation.md)). The app generates `X-Request-ID` and starts a new trace for each request, linked to an incoming `traceparent`; incoming baggage is ignored; spans' `client.address` is the resolved client, not `X-Forwarded-For`. New `APP_TRUSTED_CALLERS` lists callers whose request IDs and trace context are kept (HTTP-1, HTTP-5) | If a gateway or internal service assigns request IDs or traces you rely on, set `APP_TRUSTED_CALLERS` to its ranges (client addresses after `APP_TRUSTED_PROXIES`; list your load balancer only if it sets those headers itself and drops clients' values). `orb upgrade` brings `config.go`, `app.go` and `routes.go`. Library users: `httpx.RequestID()` no longer accepts incoming IDs; use `httpx.RequestIDFrom(ranges)` and pass `telemetry.WithTraceContextFrom(ranges)` to `Setup` |
| **Unverified accounts are deleted after 7 days** by `auth_cleanup` (`auth.unverified_account_ttl`), freeing their addresses; accounts with a Google or Apple sign-in are kept ([ADR-0038](../adr/0038-authentication-v0-2.md)) | If you create unverified accounts on purpose (for example, invitations to set a password later), raise the setting **before deploying**: `PUT /ops/settings/auth.unverified_account_ttl` up to `2160h` with a reason. The first run after upgrading deletes existing unverified accounts older than the TTL, up to 10 000 per run |
| **More changes need a reason** ([ADR-0033](../adr/0033-background-jobs.md), [ADR-0037](../adr/0037-email-setup-and-delivery.md)). Settings `mail.from_name`, `mail.from_email`, `mail.reply_to`, `auth.verification_code_ttl`, and in multi-tenant apps `orgs.invitation_url` and `orgs.invitation_ttl` (OPS-9); changing a job's timeout, `max_attempts` or queue, and pausing a queue (OPS-2) | Scripts calling `PUT /ops/settings/…` for these keys, `PUT /ops/jobs/definitions/…` with those fields, or `POST /ops/queues/{name}/pause` must send `"reason"` (otherwise 422 `setting_reason_required` or `job_reason_required`). `orb upgrade` brings the ops module changes |
| **`jobs.Manager.PauseQueue` always returns `ErrReasonRequired`** (deprecated) | Code of your own calling `PauseQueue` must switch to `PauseQueueWithReason(ctx, name, reason)`; interfaces listing `PauseQueue`/`ResumeQueue` should list `PauseQueueWithReason`/`ResumeQueueWithReason`. The Full apps' ops module does this after `orb upgrade` |
| **v1.1: Run the new migrations before deploying.** Full apps gain `20260918000001_settings_org_values.sql`, `20260918000040_idempotency_keys.sql` and `20260918000050_mail_suppressions.sql`; multi-tenant apps also `20260918000002_settings_org_purge.sql` (see Database below) | `orb upgrade`, then `go run ./cmd/migrate` before the new version serves traffic: the idempotency middleware and the mail worker read the new tables |
| **v1.1: Idempotency keys** ([ADR-0060](../adr/0060-idempotency-keys.md), [guide](idempotency.md)). Signed-in POST and PATCH requests (outside `/v1/auth/`) that send `Idempotency-Key` get the stored response on a retry instead of running again; responses are kept for `idempotency.retention` (24 h). New module `modules/idempotency`, `internal/app/idempotency.go`, middleware in `routes.go` | Handlers of your own that return a secret once (such as a new key or token) must call `idempotency.DontStore(ctx)`, or a request sent with the header stores that secret for the retention period. `orb upgrade` brings the rest. Regenerate `api/` (`go run ./cmd/api openapi --dir api`) and record `api/surface.json` (`go test ./internal/app -run TestPublicSurface -update`) |
| **v1.1: Email suppression list and Resend webhooks** ([ADR-0062](../adr/0062-resend-webhooks-and-suppression-list.md), [email guide](email.md#bounces-complaints-and-the-suppression-list)). The mail worker no longer sends to addresses on the suppression list: such jobs are cancelled with `every recipient is on the suppression list`. Resend reports hard bounces and complaints to `POST /v1/webhooks/resend` when `RESEND_WEBHOOK_SECRET` is set (404 otherwise). New module `modules/mail/suppressionpg`, app module `internal/modules/mailevents`, `internal/app/module_mailevents.go`, `webhookReader()` in `infra_mail.go` | Nothing is suppressed until you connect the webhook: in Resend, add a webhook for `email.bounced` and `email.complained` pointing at `https://<your API>/v1/webhooks/resend` and set `RESEND_WEBHOOK_SECRET` to its signing secret on every instance (a malformed secret stops the app at start). SMTP apps get the list but no webhook. If you customised `infra_mail.go` by hand, add the `webhookReader` method (see the recipe) |

### Frontends, scripts and data to check

| Change | What to do |
|---|---|
| **Google and Apple sign-in link an existing account only for addresses the provider manages** (Gmail, the account's Google Workspace domain, iCloud, Apple relay). Others get 403 `social_link_required` (web: `#error=social_link_required`); the signed-in owner links with the new `POST /v1/auth/identities` ([ADR-0046](../adr/0046-google-and-apple-sign-in.md), AUTH-M-1) | `orb upgrade` brings the endpoint and use cases. Frontends: on `social_link_required`, ask the person to sign in with their password, then link with an ID token (Google Identity Services, Sign in with Apple JS or the native SDKs) and a nonce from `POST /v1/auth/{provider}/nonce`. Existing links are kept; to review links made by the old rule, compare `auth_identities.email` domains with the rule above |
| **Accounts that Google or Apple sign-in creates for an address the provider doesn't manage are unverified** (`email_verified` false) until verified by email; proving the address by email while not signed in to that account ends its sessions and removes the provider link | Nothing for Gmail, Workspace, iCloud or Apple relay addresses. Frontends: offer "verify your email" to such users while they are signed in. Accounts created before stay verified; to review them, list `auth_identities` whose email domain isn't one the provider manages |
| **Registering again before verifying keeps the password only if it's the same.** A different password removes it; verifying an address (code, password reset, Google or Apple link) ends sessions and removes passkeys, authenticator app, recovery codes and identities added before (AUTH-S-1) | Frontends: after verifying, if sign-in answers `invalid_credentials`, offer "forgot password". Accounts verified earlier with a password set by an earlier registrant can't be told apart; if you suspect pre-registration abuse, look for `auth.user.registered` followed by verification from a different IP and ask those users to reset their password |
| **`grant-role` refuses accounts whose email address isn't verified** | Have the user verify (or reset the password) first. Roles already granted to unverified accounts stay; find them with `SELECT u.id FROM auth_users u JOIN auth_user_roles r ON r.user_id = u.id WHERE u.email_verified_at IS NULL AND u.deleted_at IS NULL` and revoke them |
| **Email addresses with uppercase non-ASCII letters or case-folding look-alikes (such as the Kelvin sign) are refused** as `invalid_email` (`auth.NormalizeEmail`, AUTH-S-3) | Existing accounts keep working when their owners type the address in lowercase. To find accounts registered with such addresses: `SELECT id FROM auth_users WHERE deleted_at IS NULL AND email <> lower(email) AND email ~ '[^[:ascii:]]'`; review them, since a look-alike may hold someone else's normalized address |
| **New recovery codes have 16 characters** (`xxxx-xxxx-xxxx-xxxx`, 80 bits) (AUTH-M-4) | Existing codes keep working. Frontends that check code length: accept up to 19 characters. If your database or a backup may have leaked, ask users with two-factor authentication to replace their codes (`POST /v1/auth/mfa/recovery-codes`) |
| **Multi-tenant apps: organisations and invitations need a verified address and have per-user limits.** A user owns at most `orgs.max_owned` (20) organisations and sends at most `orgs.user_invitations_per_hour` (50) invitations across organisations; new error code `too_many_orgs` (409) ([ADR-0048](../adr/0048-organisations-v0-4.md), ORG-3) | Raise the settings through `/ops/settings` (reason required) if your product needs more. Frontends: handle 403 `email_not_verified`, 409 `too_many_orgs` and 429 `too_many_invitations` on create, invite and resend |
| **Multi-tenant apps: invitations are accepted only while the member who sent or last resent them may still give that role** (ORG-1) | Invitations from people who have since left or been demoted stop working (404 `invitation_not_found`); resend them from a current owner or admin |
| **Multi-tenant apps that added organisation roles: members may give only roles whose permissions their own role holds** (ORG-2); restoring an organisation needs the same second factor as deleting it (ORG-5, new `orgs.Authorize`) | Nothing unless you relied on admins assigning a more powerful custom role. Update `gorbital.dev/modules/orgs` with the upgrade |
| **Multi-tenant apps: deleted accounts leave every organisation, including deleted ones**, and memberships of deleted accounts no longer count as owners (ORG-6) | Memberships left by accounts deleted earlier can be removed by an owner; find them with `SELECT m.org_id, m.user_id, m.role FROM org_members m JOIN auth_users u ON u.id = m.user_id WHERE u.deleted_at IS NOT NULL` (they also go when the account is purged) |
| **Job run controls** ([ADR-0033](../adr/0033-background-jobs.md)): run-now is refused with 429 `job_run_limited` while a run is queued or running or within a minute of the last (OPS-2); retry works only for runs waiting to retry, discarded or cancelled, of enabled jobs, otherwise 409 `job_not_retryable` or `job_definition_disabled` (OPS-3) | Scripts that run or retry jobs: handle the new answers. `orb upgrade` adds the error mappings in `module_ops.go` |
| **Audit listings and stats stop after 5 seconds** with 503 `audit_query_timeout` (OPS-6) | Narrow queries with `from`/`to` or an indexed filter. `orb upgrade` adds the error mapping |
| **`POST /ops/mail/test` allows 5 test emails an hour per operator** (429 `rate_limited`) and no longer answers 403 after queueing for roles without `ops.mail.read` (OPS-8) | Nothing beyond `orb upgrade` |
| **HTTP server metrics no longer carry `server.address` and `server.port`** (HTTP-2) | Dashboards or alerts grouping HTTP metrics by them: group by `http.route` instead |
| **Audit metadata redaction also covers plural and camelCase keys** (`tokens`, `apiKeys`, `recovery_codes`) and more names (`totp`, `jwt`, `bearer`, `pin`, qualified codes) (OPS-4) | Automatic. Values under such keys, including counts, now show `[REDACTED]` (for example `secrets` in `auth.keys.rotated`). A bare `code` key isn't redacted; add it with `auditpg.WithRedactedKeys("code")` if yours holds secrets |
| **Minimal apps: grpc v1.83.2** (GO-2026-6443, imported but not called); build with the latest Go patch release (CLI-7) | `go get google.golang.org/grpc@v1.83.2 && go mod tidy`. Build `orb` and apps with Go 1.26.5 or newer; `orb version` and `orb doctor` warn otherwise |
| **`orb upgrade` reads earlier releases only from a gorbital checkout that is its own git repository outside the app**, and without a checkout refuses `GOSUMDB` other than sum.golang.org or sum.golang.google.cn and `GOPRIVATE`, `GONOSUMDB` or `GOINSECURE` patterns covering `gorbital.dev`, trailing slash included (CLI-3, CLI-5) | A `replace` to a copy inside the app is ignored (the module proxy is used); `--local` inside the app is refused. Unset those variables for the upgrade or pass `--local` with a checkout outside the app |
| **`orb` checks `gorbital.lock` and `gorbital.yaml`** (app name, module path, preset, tenancy, mail provider) before rendering templates (CLI-4) | Nothing for values `orb` wrote. A hand-edited lock with invalid values stops `orb upgrade`, `orb add orgs` and `orb add mail` |
| **`orb add mail` makes `.env` mode 0600** and warns if it was readable by others (CLI-2) | If your `.env` came from `cp .env.example .env`, run `chmod 600 .env` |
| **`orb` built from a checkout before commit `67261e3`** could copy `examples/full-single/.env` into new apps (CLI-1) | Only if you installed `orb` from a checkout that had that file: reinstall, check apps created with it for a stray `.env` from the golden app, and rotate `AUTH_ENCRYPTION_KEYS` if one leaked. Maintainers: `go generate ./internal/recipes/` now needs git |
| **v1.1: CORS allows `Idempotency-Key` and exposes `Idempotent-Replayed`** ([ADR-0060](../adr/0060-idempotency-keys.md)). A request reusing a key for a different body gets 422 `idempotency_key_reused`, one still running 409 `idempotency_in_progress`, a malformed key 400 `invalid_idempotency_key` | Clients that don't send the header see no change. Frontends and mobile apps that retry POST or PATCH: send a new key per logical operation and the same key on retries. If you pass your own `AllowedHeaders`/`ExposedHeaders` to `httpx.CORS`, add the two headers |
| **v1.1: Span names are route patterns in Full apps** (`GET /v1/projects/{id}` instead of `GET`) and HTTP metrics carry `http.route`: `routes.go` wraps the mux with `telemetry.RecordRoute` ([ADR-0063](../adr/0063-prometheus-metrics.md)) | Dashboards or alerts filtering spans named `GET`/`POST` should use the route names. If you changed `routes.go`'s `httpx.Chain(mux, …)` line, resolve the merge as `httpx.Chain(telemetry.RecordRoute(mux), …)` |
| **v1.1: More metrics over OTLP**: Go runtime (`go.*`) and connection pool (`db.client.connection.*`, `pgxpool.*`) metrics, and HTTP metrics per route | With `OTEL_EXPORTER_OTLP_ENDPOINT` set, expect more series at your backend (about 20 runtime and pool series per instance, plus one set of HTTP histograms per route and status instead of per status) |
| **v1.1: Multi-tenant apps: organisation settings permissions** `orgs.settings.read` (owner, admin, member) and `orgs.settings.write` (owner, admin) ([ADR-0056](../adr/0056-per-organisation-settings.md)) | Custom organisation roles in `declareOrgPermissions` don't get them unless you add them. Before marking your own settings `OrgOverridable`, read the [guide](runtime-settings.md): never for sign-in, rate limits, retention, maintenance, email senders or link targets; `TestSecuritySettingsArentOrgOverridable` checks the built-in groups |
| **v1.1: `ops.mail.write`** removes addresses from the suppression list; it's in `platform_admin` only ([ADR-0062](../adr/0062-resend-webhooks-and-suppression-list.md)) | Nothing; `ops_viewer` lists suppressions (`ops.mail.read`) but can't remove them. Support scripts: a user who gets no email may be suppressed (`GET /ops/mail/suppressions`); remove with a reason. Tests comparing `GET /ops/mail` details for Resend get `webhook_secret` in the fixture from the new `infra_mail_test.go` |

### Automatic

| Change | What to do |
|---|---|
| **Rate limits are shared by every instance** ([ADR-0052](../adr/0052-shared-rate-limits.md)). Sign-in, per-IP and two-factor limits are counted in PostgreSQL (`modules/ratelimitpg`), so an app running several instances no longer allows several times each limit. They became runtime settings: `auth.login_attempts` (10), `auth.login_window` (15 min), `auth.ip_requests_per_minute` (60), `auth.mfa_change_attempts` (10) | Nothing for one instance. With several, effective limits get stricter: raise the settings if your traffic needs it |
| **The sign-in limit counts per address and client network** (`auth.login_attempts`, an IPv4 address or IPv6 /64), with a looser per-address limit across networks, `auth.login_address_attempts` (50 per `auth.login_window`). Wrong passwords from elsewhere no longer lock the owner out after 10 (AUTH-S-6) | Nothing. Existing `auth_login` buckets expire unused |
| **Per-IP rate limits group IPv6 clients by /64** (`ratelimit.ByRemoteIP`, new `ratelimit.ClientKey`) (AUTH-S-7) | Nothing. Clients sharing a /64 share the `auth.ip_requests_per_minute` budget |
| **Code checks are limited per address across codes**: `auth.code_attempts` (20) per `auth.code_window` (24 h) for verification and reset codes, shared by instances (AUTH-S-2) | Nothing. After the budget even the right code is refused until the window passes; password sign-in is unaffected |
| **Changes that check the password or a second factor of a signed-in user are limited per user**: `auth.reauth_attempts` (10 per `auth.login_window`) for password change, authenticator app setup and removal, passkey add and remove, linking and unlinking Google or Apple, and account deletion; failures are audited as `auth.reauth.failed` (AUTH-S-5, AUTH-M-2) | Nothing. Dashboards filtering audit actions may add `auth.reauth.failed` |
| **Registration, resending a code and forgot password take at least 300 ms**, whether or not the address has an account (AUTH-S-4) | Nothing. Load tests of those endpoints see the floor |
| **Password hashing waits at most 5 seconds for its turn**, then answers 503 `auth_unavailable`; wrong reset codes no longer cost a hash (AUTH-S-8) | Nothing. `auth.NewHasherWith(auth.WithHashConcurrency(n), auth.WithHashMaxWait(d))` tunes it for your own use |
| **Apple notifications older than an hour are refused and each is processed once** (AUTH-M-3) | Nothing |
| **Audit events recorded during a request carry the client IP and user agent** (settings, jobs, queues, test emails, every module's) (OPS-7) | Nothing for apps using `auth.Middleware`. Apps without it can call `actor.WithClient` in their own middleware after `httpx.TrustedProxies` |
| **Email addresses in mail provider errors are replaced with `[email]`** in job runs and logs (OPS-5) | Nothing. Errors your own workers store aren't rewritten |
| **`/readyz` shares one run of its checks among concurrent requests** and reuses the result for 1 s (HTTP-7) | Nothing. A dependency failure shows up to 1 s later |
| **Multi-tenant apps: the `orgs_purge` job clears its whole backlog per run** (up to 5 minutes); organisation use cases re-read the caller's role under the organisation lock; invitation changes lock in one order (ORG-3, ORG-4, ORG-7) | Nothing beyond `orb upgrade`. Requests from a member removed or demoted a moment before fail with 404 or 403 |
| **`settings.StringList` without `MaxItems` is limited to 100 items** (OPS-10) | Nothing. Declare `MaxItems(n)` for more |
| **Apple tokens are revoked by a job.** Unlinking Apple or deleting an account queues the token in `auth_token_revocations`; the new `auth_revoke_tokens` job (every minute) revokes it and retries failures ([ADR-0046](../adr/0046-google-and-apple-sign-in.md)) | Nothing: `orb upgrade` adds the job and migration. Account deletion no longer waits on Apple |
| New job `ratelimit_cleanup` (hourly) | Nothing |
| **Public names are recorded and checked** ([ADR-0054](../adr/0054-api-freeze-and-scaffold-compatibility.md)). Full apps gain `api/surface.json` (error codes, audit actions, permissions and roles, setting keys, job names), `api/openapi.baseline.json` (the `/ops` contract), and the tests `TestPublicSurface` and `TestOpsAPICompatible` in `internal/app`; `permissions.go` gains `permissionCatalogs` | Nothing: `orb upgrade` adds the files and records `api/surface.json` from your code, including your own resources and jobs; review it in the upgrade commit. From then on, after `orb gen resource`, `orb gen job` or adding a code, action, permission, setting or job by hand, run `go test ./internal/app -run TestPublicSurface -update` and commit the file. A test failure for a recorded name means you removed something clients may use. [Stability and compatibility](stability.md) |
| **`orb --json` output starts with `"schemaVersion": 1`**; `orb version --json` is new | Scripts that read `--json` keep working (a field was added). Check `schemaVersion` from now on |
| New public names from the security review: error codes `social_link_required`, `identity_in_use`, `too_many_orgs`, `job_run_limited`, `job_not_retryable`, `audit_query_timeout`; audit actions `auth.reauth.failed`, `auth.accounts.unverified_expired`; settings `auth.login_address_attempts`, `auth.reauth_attempts`, `auth.code_attempts`, `auth.code_window`, `auth.unverified_account_ttl`, and in multi-tenant apps `orgs.max_owned`, `orgs.user_invitations_per_hour`; endpoint `POST /v1/auth/identities` | Nothing: `orb upgrade` records them in `api/surface.json`. The `/ops` baseline is unchanged |
| **v1.1: Per-organisation settings** ([ADR-0056](../adr/0056-per-organisation-settings.md)). Settings declared `settings.OrgOverridable()` take a value per organisation. Multi-tenant apps gain `/v1/orgs/{orgId}/settings` for members (read) and owners and admins (change), with `orgs.invitation_ttl` as the one overridable setting; all Full apps gain `GET /ops/settings/{key}/overrides` and `org_overridable` in setting responses | Nothing: `orb upgrade` adds the files and records the new permissions in `api/surface.json`. The `/ops` baseline check passes (fields and an operation added) |
| **v1.1: Prometheus metrics option** ([ADR-0063](../adr/0063-prometheus-metrics.md)). `METRICS_ADDR` starts a second listener serving only `GET /metrics`, without authentication; off by default, in every preset | Nothing unless you want it: `orb upgrade` adds `internal/app/metrics.go` and the wiring. To turn it on, set `METRICS_ADDR` to a private interface or an unpublished container port (such as `0.0.0.0:9464` in a container whose port isn't exposed), never the API's port (refused at start), and scrape every instance ([production](production.md#prometheus-metrics)) |
| **v1.1:** new job `idempotency_cleanup` (hourly), setting `idempotency.retention` (24 h, 1 h to 7 days, reason required) and `idempotency_keys` in `GET /ops/retention` | Nothing |
| **v1.1:** new public names: error codes `invalid_idempotency_key`, `idempotency_in_progress`, `idempotency_key_reused`, `webhook_not_found`, `invalid_webhook_signature`, `invalid_webhook_payload`, `mail_suppression_not_found`, `mail_suppression_reason_required`; audit actions `mail.suppression.added`, `mail.suppression.removed`; permissions `ops.mail.write`, and in multi-tenant apps `orgs.settings.read`, `orgs.settings.write`; setting `idempotency.retention`; job `idempotency_cleanup`; environment variables `METRICS_ADDR` and `RESEND_WEBHOOK_SECRET` | Nothing: `orb upgrade` records them in `api/surface.json` |
