# Your main.go

In a v0.2 app, `cmd/api/main.go` is the whole composition root: one call to `gorbital.Main` that names what the app contains. gorbital loads the configuration, builds the database pool, stores, job workers, email delivery and middleware in a fixed order, serves the API, and shuts it all down cleanly. Your code is your modules and your migrations. The package is `gorbital.dev/gorbital` ([Methods](../methods/gorbital.md)); the decisions are [ADR-0081](../adr/0081-a-framework-you-import.md) and [ADR-0083](../adr/0083-modules-stack-migrations-and-ejection.md).

> **Status: v0.2.** `gorbital.Main` is in the library, with sign-in (`gorbital.dev/gorbital/authhttp`, [Methods](../methods/gorbital-authhttp.md)) and the built-in modules for `/ops`, `/v1/flags`, organisations and the email webhook. Together they serve what a v0.1 app's generated modules served, including the sign-in methods, rate limiters and accounts retention in `/ops`. Sign-in takes options and hooks ([below](#sign-in-options)). Apps generated by `orb` v0.1 keep their `internal/app` and work unchanged.

## The file

| Option | What it adds |
|---|---|
| `WithName("shelfie")` | The service name in logs, traces and metrics, the OpenAPI title and the database connections' application name. Without it, the last element of the module path |
| `WithModules(opshttp.Module(), flagshttp.Module())` | Built-in modules, one line each: the operations API under `/ops/`, and the feature flags clients read ([below](#built-in-modules)) |
| `WithModules(orgshttp.Module(auth))` | Organisations: `/v1/orgs/…`, `/v1/invitations` and organisations' service accounts. It takes the app's authenticator, the same value as `WithAuth` ([organisations](../start/organisations.md#in-an-app-on-gorbitalmain)) |
| `WithModules(modules.All()...)` | The app's modules. `modules.All` is generated from `internal/modules` ([below](#the-module-list)) |
| `WithMigrations(migrations.FS)` | The app's own migrations, the embedded `db/migrations` |
| `WithAuth(authhttp.New())` | Sign-in: its middleware sets who is calling, and it adds the `/v1/auth/*`, `/ops/auth/users` and `/ops/service-accounts` routes, sign-in's permissions, settings, jobs, migrations and [commands](#sign-in-commands) ([authentication](authentication.md#where-the-code-lives)). `authhttp.New` takes [options](#sign-in-options). Or your own `gorbital.Authenticator`. Without it, every route that isn't `guard.Public()` answers 401 |
| `WithStorage(s)`, `WithStorageFunc(open)` | File storage other than the local driver, such as S3 ([configuration](environment-variables.md#apps-on-gorbitalmain)) |
| `WithMailer(s)`, `WithMailerFunc(open)` | The email provider for `MAIL_DELIVERY=provider`, which production requires |
| `WithMiddleware(mw...)`, `WithMiddlewareFunc(build)` | Your middleware, after the built-in stack ([the middleware stack](middleware-stack.md)) |
| `WithStack(build)` | A different order for the built-in stack |
| `WithLogger(logger)` | Your own `*slog.Logger` instead of the one built from `APP_LOG_LEVEL` and `APP_LOG_FORMAT` |

Every option is a line you can read: nothing is on because of a default you can't see, and an app compiles only the drivers it names.

## Sign-in options

`authhttp.New()` without options is v0.1's sign-in. Options change it in `main.go`, where the rest of the app is composed:

```go
func main() {
	auth := authhttp.New(
		authhttp.MinPasswordLength(14),
		authhttp.RequireMFA("billing_admin"),
		authhttp.OnRegister(createProfile),
	)
	gorbital.Main(
		gorbital.WithName("shelfie"),
		gorbital.WithAuth(auth),
		gorbital.WithModules(opshttp.Module(), flagshttp.Module()),
		gorbital.WithModules(modules.All()...),
		gorbital.WithModules(phonelogin.Module(auth, newSMSSender())),
		gorbital.WithMigrations(migrations.FS),
	)
}
```

- Keep the authenticator in a variable when a module needs it. A module that adds a sign-in method takes it as an argument, so `orb gen modules` doesn't list it: add it with its own `WithModules` ([adding a sign-in method](adding-a-sign-in-method.md)).
- An invalid option, such as `MinPasswordLength(8)`, is a configuration error: exit status 2 before anything connects.
- Every option: [configuring sign-in](configuring-sign-in.md). Hooks: [sign-in hooks](sign-in-hooks.md). Registration fields: [extra registration fields](extra-registration-fields.md).

## Built-in modules

gorbital's own modules are packages of `gorbital.dev/gorbital`, added like yours with `WithModules`. Each serves the endpoints a v0.1 app generated, with the same paths, schemas, error codes and permissions:

| Module | Serves | Guide |
|---|---|---|
| `opshttp.Module(opts...)` | `/ops/`: runtime settings, flags, jobs, audit log, releases, email, storage, system, retention, rate limits, observability and incidents; `OPS_ALLOWED_IPS` limits who can reach it | [Ops API](ops-api.md#adding-it-to-an-app) |
| `flagshttp.Module()` | `GET /v1/flags`, the flags clients read | [Feature flags](feature-flags.md) |
| `orgshttp.Module(auth, opts...)` | `/v1/orgs/…` and `/v1/invitations`: organisations, their members, invitations, settings and service accounts. It takes the app's authenticator, because members are its accounts | [Organisations](../start/organisations.md#in-an-app-on-gorbitalmain) |
| `mailevents.Module()` | `POST /v1/webhooks/resend`, Resend's bounces and complaints, when `RESEND_WEBHOOK_SECRET` is set | [Email](email.md) |

```go
gorbital.Main(
	gorbital.WithModules(opshttp.Module(), flagshttp.Module(), mailevents.Module()),
	gorbital.WithModules(modules.All()...),
	gorbital.WithMigrations(migrations.FS),
)
```

Leave out what the app doesn't serve: an app without `/ops` doesn't compile it. What `/ops` reports comes from every module: your modules' settings, flags and jobs, the rate limiters and retention they declare ([modules and routes](modules-and-routes.md#a-module)). In development, `orb dev`'s dev console token operates `/ops/` for the Dev Portal.

## Commands

The first argument chooses what the program does:

| Command | What it does | Needs |
|---|---|---|
| `serve` (or nothing) | Loads the configuration, builds the app and serves it until SIGINT or SIGTERM | `APP_ENV`, `DATABASE_URL` |
| `migrate` | Applies pending migrations: the library's, the modules' and yours in one history, then River's job tables | `APP_ENV`, `DATABASE_URL` |
| `migrate --status [--json]` | Reports pending migrations and changes nothing; `orb doctor` reads the JSON | Same |
| `migrate-down` | Rolls back your most recent migration. Development only | Same |
| `openapi [--dir api]` | Prints the OpenAPI document, or writes `openapi.json`, `postman_collection.json` and `llms.txt` into the directory. Reads no environment and needs no database: modules register their routes with zero `Deps` | Nothing |
| `version [--json]` | Prints the build's version, commit and Go version | Nothing |
| `help` | Lists the commands, including those modules add | Nothing |

```bash
go run ./cmd/api migrate
go run ./cmd/api                       # serve
go run ./cmd/api openapi --dir api
```

The server never migrates on its own ([ADR-0017](../adr/0017-application-lifecycle.md)): run `migrate` before starting a new version, as a release step. When migrations are pending, the server logs a warning at start.

Built-in modules add commands of their own, which `help` lists.

### Sign-in commands

With `gorbital.WithAuth(authhttp.New())`, `Main` serves the commands of v0.1's `cmd/api`, with the same names, arguments and output:

| Command | What it does | Needs |
|---|---|---|
| `roles` | Lists the platform roles and their permissions | `APP_ENV` |
| `grant-role <email> <role>` | Gives a verified account a platform role, recorded in the audit log as `cli` | `APP_ENV`, `DATABASE_URL` |
| `revoke-role <email> <role>` | Takes a platform role away | Same |
| `reset-mfa <email>` | Turns off an account's two-factor authentication and ends its sessions | Same |
| `rotate-auth-keys` | Re-encrypts two-factor secrets with the first `AUTH_ENCRYPTION_KEYS` key | Same, and `AUTH_ENCRYPTION_KEYS` |
| `auth-providers` | Prints which sign-in methods are configured, and what to set for the others | `APP_ENV` |
| `seed [--email <email>]` | Creates a development administrator with two-factor authentication on, printing its password, key and recovery codes once. It changes nothing when the account exists, so `orb dev` runs it on every start, and it refuses to run when `APP_ENV` is production | `APP_ENV`, `DATABASE_URL`, `AUTH_ENCRYPTION_KEYS` |

```bash
go run ./cmd/api grant-role you@example.com platform_admin
```

One difference from v0.1: wrong arguments, such as a missing email, exit with status 2 (`gorbital.ErrUsage`), where v0.1's `cmd/api` exited with 1 for every error. Other failures, such as an unknown account, still exit with 1.

### Exit codes

| Code | When |
|---|---|
| 0 | Success, and a clean shutdown |
| 1 | A runtime error: the database is unreachable, a migration failed, the server stopped unexpectedly |
| 2 | A usage or configuration error: an unknown command or flag, wrong arguments to a command, an invalid environment variable (including those sign-in checks, such as a missing `AUTH_ENCRYPTION_KEYS` in production), a production-only refusal such as `migrate-down` with `APP_ENV=production`, or a missing provider (`MAIL_DELIVERY=provider` without `WithMailer`) |

Every configuration problem is reported at once, one line per variable:

```text
shelfie: invalid configuration:
APP_ENV must be development or production, got "staging"
APP_CORS_ORIGINS: "http://app.example.com" must use https in production
```

## What serve builds, in order

1. **Logging and telemetry**: the logger, traces and metrics (OTLP when `OTEL_EXPORTER_OTLP_ENDPOINT` is set), the metrics listener on `METRICS_ADDR`, the dev console's log buffer and the hourly log archive.
2. **PostgreSQL**: the pool, its readiness check, and warnings for pending migrations and row-level security problems.
3. **The audit log** (`audit_events`).
4. **Declarations**: the built-in runtime settings (`mail.*`, `maintenance.*`, retention and incidents), then every module's permissions, settings and flags. A duplicate stops the start naming both modules.
5. **Stores**: runtime settings and feature flags, loaded before anything serves.
6. **Email delivery**: SMTP to `orb dev`'s mail catcher or Mailpit in development, your provider in production, skipping suppressed addresses.
7. **Shared rate limits, idempotency keys, file storage, request metrics.**
8. **Jobs**: the built-in cleanup, incident and retention jobs, then every module's `Jobs`, then the job client and its definitions manager.
9. **The mailer modules use** (`Deps.Mailer`): it queues each email as a job, with the sender from the `mail.*` settings.
10. **Release tracking and the request collector**, and in development with `DEV_CONSOLE_TOKEN` the [dev console](dev-console.md).
11. **The platform** built-in modules read: the job manager, health checks, the rate limiters and retention every module declared (`Module.Platform`); a module refusing its configuration stops the start here.
12. **The API**: `/version`, every module's routes, `/docs` when enabled, `/livez` and `/readyz`.
13. **The middleware stack** around it ([the middleware stack](middleware-stack.md)).

Every step is a public constructor of a library module, so you can read what it does, or do it yourself.

## Shutting down

On SIGINT or SIGTERM, `serve`:

1. makes `/readyz` answer 503, so load balancers stop sending traffic;
2. waits the drain delay: 5 seconds in production, none in development;
3. stops taking requests and lets the server and the workers (settings and flags listeners, the job client and definitions manager, the release heartbeat, the request collector, the metrics listener) finish, for up to 25 seconds;
4. closes resources in the reverse order they were opened: the dev console, the database pool, the log archive, telemetry last.

A second signal during shutdown stops at once.

## Without Main

`Main` is a convenience over three calls you can make yourself, for example to serve the app inside another server or to run it from your own command-line tool:

```go
ctx := context.Background()
cfg, err := gorbital.LoadConfig(config.OS)
if err != nil {
	log.Fatal(err)
}
opts := []gorbital.Option{gorbital.WithModules(modules.All()...), gorbital.WithMigrations(migrations.FS)}
app, err := gorbital.New(ctx, cfg, opts...)
if err != nil {
	log.Fatal(err)
}
log.Fatal(app.Run(ctx))
```

`app.Handler()` is the whole API behind the middleware stack, `app.Deps()` the dependencies modules receive, and `app.Close(ctx)` releases everything when `Run` isn't called. `gorbital.Migrate(ctx, cfg, os.Stdout, opts...)` applies migrations.
