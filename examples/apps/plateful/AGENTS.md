# Guide for AI coding assistants

This is a Go API generated by gorbital, running on `gorbital.Main`. Read [ARCHITECTURE.md](ARCHITECTURE.md) before changing code.

## Commands

| Purpose | Command |
|---|---|
| Run locally: services, migrations, seed data, reload | `orb dev` |
| Start PostgreSQL | `docker compose up -d --wait` |
| Apply migrations | `go run ./cmd/api migrate` (`--status` reports pending ones) |
| Seed a development database (`admin@example.com`, whose personal workspace is created when it first lists its organisations; password, 2FA key and recovery codes printed once) | `go run ./cmd/api seed` |
| Test (must pass before finishing) | `GORBITAL_TEST_DATABASE_URL=postgres://plateful:plateful@127.0.0.1:5432/plateful?sslmode=disable go test ./...` |
| Vet | `go vet ./...` |
| Run the API only | `go run ./cmd/api` |
| List every command | `go run ./cmd/api help` |
| Check the app's setup (module list, stack, migrations, configuration) | `orb doctor` |
| List routes with their guards, middleware and source | `orb routes` |
| Inspect the running app: recent requests and logs, routes, configuration without secrets, captured email, migrations, job runs | `curl -H "Authorization: Bearer <token printed by orb dev>" http://127.0.0.1:8080/_dev/` (development only; shapes in `/_dev/openapi.json`) |
| Update the API contract (openapi.json, Postman collection, llms.txt) after changing endpoints | `go run ./cmd/api openapi --dir api` |
| Record new error codes, audit actions, permissions, settings, jobs or feature flags (public API: never remove one that is recorded) | `go test ./internal/modules -run TestPublicSurface -update`, then commit `api/surface.json` |
| Check `/ops` still works for existing clients | `go test ./cmd/api -run TestOpsAPICompatible` (never edit `api/openapi.baseline.json` to make it pass) |
| Give an account a platform role | `go run ./cmd/api grant-role <email> <role>` (`go run ./cmd/api roles` lists them); `platform_admin` and `ops_viewer` work only in sessions signed in with two-factor authentication |
| Turn off an account's 2FA (lost authenticator app and recovery codes) | `go run ./cmd/api reset-mfa <email>` |
| Replace the 2FA encryption key | Put a new key first in `AUTH_ENCRYPTION_KEYS` on every instance, run `go run ./cmd/api rotate-auth-keys`, then remove the old key |
| Let a script or service call the API | An API key: `POST /v1/auth/api-keys` (acts as you), or a service account with a role that doesn't require 2FA and its keys (`/ops/service-accounts`); keys are shown once and never reach `/ops` |
| Configure sign-in methods (passkeys, iOS and Android apps, Google, Apple, GitHub) | Set the variables in `.env` following `AUTH_PROVIDERS.md`; check with `go run ./cmd/api auth-providers`; never commit the values |

## Where code goes

| Change | Location |
|---|---|
| New module: a table and its API that belong to organisations | `orb gen module <Name> <field:type>... --org --yes` (types `string`, `string:unique`, `string?`, `text`, `'enum(a,b)'`), then `go run ./cmd/api migrate`; it creates a module like `internal/modules/projects/` and updates `modules.gen.go`. Keep `guard.OrgMember` on every route, the organisation ID in every query and the cross-organisation tests |
| New module by hand | `internal/modules/<module>/module.go` with `func Module() gorbital.Module`, then `orb gen modules` (orb dev runs it); never edit `modules.gen.go` |
| Business rule or domain error | `internal/modules/<module>/domain/` |
| Application logic | `internal/modules/<module>/usecase/<operation>.go`; interfaces for storage or external services in `usecase/ports.go` |
| SQL query | `internal/modules/<module>/repository/<operation>.go` (hand-written SQL, one file per statement) |
| HTTP endpoint | The route and its guards in `internal/modules/<module>/delivery/routes.go` (`gorbital.Get`, `gorbital.Post`, …), its input, output and handler in `delivery/<operation>.go` |
| Who may call a route | Guards on the route: every route requires sign-in unless `guard.Public()`; `guard.Permission(p)`, `guard.RecentReauth()`, `guard.RateLimit(n, window)`, or your own with `orb gen middleware <name> --module <module> --guard` |
| Domain error → HTTP status and error code | The module's `Errors` in `module.go` |
| Permission or platform role | The module's `Permissions` in `module.go`, with the `Roles` that hold it; check it with `guard.Permission` on the route. Something every signed-in user may do outside an organisation still needs a permission, given to the `user` role, or API key scopes don't limit it |
| Permission inside organisations | The module's `Permissions` with `OrgRoles` (`owner`, `admin`, `member`); check it with `guard.OrgMember(permission)` on a route under `/v1/orgs/{orgId}/` |
| Organisation, member or invitation rule | Options of `orgshttp.Module(auth, ...)` in `main.go`; for anything else, `orb eject orgs` |
| Tunable each organisation may choose for itself | Add `settings.OrgOverridable()` to its declaration and read it with the context `guard.OrgMember` gives the handler; never for sign-in, rate limits, retention, maintenance, email senders or link targets |
| Secret or infrastructure setting | `.env.example`, read through `gorbital.Config` (the configuration guide lists every variable); never `os.Getenv` in a module |
| Tunable operators change at runtime | The module's `Settings` in `module.go` (a runtime setting, not an env var); keep the `*settings.Setting` and call `Get` |
| Feature turned on for some organisations, users or a percentage of them | The module's `Flags` in `module.go` (`flags.Bool`, `flags.Client()` if clients need it), checked with `Enabled(ctx)` or passed on as a `config.Value[bool]`; never use a flag as access control |
| Background job | The module's `Jobs` in `module.go`: define it on `jobs.Definitions` with its code defaults; enqueue with `Deps.Jobs.Insert`, or `InsertTx` in the transaction of the change |
| Database change (column, index, table) | `orb gen migration <name> --yes`, then write the SQL under `-- +goose Up` before `go run ./cmd/api migrate` (an empty migration is recorded as applied; never edit a released migration) |
| Sign-up, sign-in or session rule | Options and hooks of `authhttp.New(...)` in `main.go` (`MinPasswordLength`, `PasswordPolicy`, `RequireMFA`, `WithoutRegistration`, `BeforeLogin`, `AfterLogin`, `OnRegister`, `RegisterFields`); for anything else, `orb eject auth` |
| Send an email | `Deps.Mailer` in the module; leave `From` empty so the `mail.*` settings apply |
| Email provider (Resend or SMTP) | `orb add mail --provider resend\|smtp --yes`; never edit `cmd/api/mail.go` or the `# orb:begin mail` block by hand. Secrets go in `.env` only |
| Email sender name, address, reply-to | Runtime settings `mail.from_name`, `mail.from_email`, `mail.reply_to` (not env vars) |
| Bounced or complained addresses | The suppression list: `/ops/mail/suppressions`, fed by `POST /v1/webhooks/resend` (`RESEND_WEBHOOK_SECRET`); the mail worker never sends to them. Don't bypass it by sending through a provider directly |
| Middleware for the whole app | `orb gen middleware <name> --global`, then add it with `gorbital.WithMiddleware` in `main.go` |

## Rules

- Keep `domain/` free of third-party imports and struct tags.
- Never read environment variables in a module.
- Never read or change an organisation's data without `guard.OrgMember` on the route, and never give platform roles access to it.
- Never set `gorbital.org_id` or `gorbital.rls_bypass` in SQL. A system path that must reach every organisation's rows under row-level security (`orb add rls`) uses `postgres.WithoutRowLevelSecurity(ctx, "job:<name>")`, never because of request input.
- Never import one module from another.
- Return domain errors from handlers; don't build HTTP errors in use cases.
- Never mark a route `guard.Public()` unless anyone on the internet may call it.
- Request body structs start with ``_ struct{} `json:"-" additionalProperties:"true"` `` so unknown fields are ignored.
- Error codes, audit actions, permissions, runtime setting keys, flag keys and job names are public API: add new ones, never rename existing ones.
- Never put secrets in runtime settings or job arguments.
- A POST or PATCH response that shows a secret once (such as a new key or token) calls `idempotency.DontStore(ctx)` in its handler, so retries with an `Idempotency-Key` don't store it.
- Never log secrets, tokens, passwords or email addresses; log IDs.
- Request counts, metrics and traces group requests by the route pattern (`GET /v1/projects/{id}`); never label them with requested paths, query strings or other values clients choose.
- Never store passwords, tokens, API keys or codes in plain text; use the auth library's `Hasher`, `NewToken`/`HashToken` and `NewCode`/`HashCode`.
- Never send email directly through a provider; use `Deps.Mailer` so it's queued, retried and caught in development.
- Never edit `internal/modules/modules.gen.go`; `orb gen modules` writes it.
