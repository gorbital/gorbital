# Guide for AI coding assistants

This is a Go API generated by gorbital. Read [ARCHITECTURE.md](ARCHITECTURE.md) before changing code.

## Commands

| Purpose | Command |
|---|---|
| Run locally: services, migrations, seed data, reload | `orb dev` |
| Start PostgreSQL and Mailpit | `docker compose up -d --wait` |
| Apply migrations | `go run ./cmd/migrate` |
| Seed a development database (`admin@example.com` with a personal workspace; password, 2FA key and recovery codes printed once) | `go run ./cmd/seed` |
| Test (must pass before finishing) | `GORBITAL_TEST_DATABASE_URL=postgres://acme-api:acme-api@127.0.0.1:5432/acme-api?sslmode=disable go test ./...` |
| Vet | `go vet ./...` |
| Run the API only | `go run ./cmd/api` |
| Update the API contract (openapi.json, Postman collection, llms.txt) after changing endpoints | `go run ./cmd/api openapi --dir api` |
| Record new error codes, audit actions, permissions, settings or jobs (public API: never remove one that is recorded) | `go test ./internal/app -run TestPublicSurface -update`, then commit `api/surface.json` |
| Check `/ops` still works for existing clients | `go test ./internal/app -run TestOpsAPICompatible` (never edit `api/openapi.baseline.json` to make it pass) |
| Give an account a platform role | `go run ./cmd/api grant-role <email> <role>` (`go run ./cmd/api roles` lists them); `platform_admin` and `ops_viewer` work only in sessions signed in with two-factor authentication |
| Turn off an account's 2FA (lost authenticator app and recovery codes) | `go run ./cmd/api reset-mfa <email>` |
| Replace the 2FA encryption key | Put a new key first in `AUTH_ENCRYPTION_KEYS` on every instance, run `go run ./cmd/api rotate-auth-keys`, then remove the old key |
| Let a script or service call the API | An API key: `POST /v1/auth/api-keys` (acts as you), or a service account with a role that doesn't require 2FA and its keys (`/ops/service-accounts`); keys are shown once and never reach `/ops` |
| Configure sign-in methods (passkeys, iOS and Android apps, Google, Apple) | Set the variables in `.env` following `AUTH_PROVIDERS.md`; check with `go run ./cmd/api auth-providers`; never commit the values |

## Where code goes

| Change | Location |
|---|---|
| Business rule or domain error | `internal/modules/<module>/domain/` |
| Application logic | `internal/modules/<module>/usecase/` |
| Interface for storage or external services | `internal/modules/<module>/usecase/ports.go` |
| SQL query | `internal/modules/<module>/repository/<operation>.go` (hand-written SQL, one file per operation) |
| HTTP endpoint | `internal/modules/<module>/delivery/` (`huma.Register`) |
| Domain error → HTTP status and error code | `internal/app/module_<module>.go` |
| Secret or infrastructure setting | `internal/app/config.go` and `.env.example` |
| Tunable operators change at runtime | `internal/app/settings.go` (a runtime setting, not an env var) |
| Background job | `orb gen job <Name> --yes [--schedule SPEC \| --every D \| --on-demand] [--timeout D] [--max-attempts N]`: creates `internal/jobs/<name>/`, `internal/app/job_<name>.go` and one line in `internal/app/jobs.go` |
| Database change outside a new resource (column, index, table) | `orb gen migration <name> --yes`, then write the SQL under `-- +goose Up` before `go run ./cmd/migrate` (an empty migration is recorded as applied; never edit a released migration) |
| Sign-up, sign-in or session rule | `internal/modules/auth/usecase/` (flows) and `internal/modules/auth/repository/` (SQL); security helpers come from `gorbital.dev/modules/auth` |
| Permission or platform role | `internal/app/permissions.go` (`declarePermissions`); check it in the use case with `actor.Can(permission)` |
| Permission or role inside organisations | `internal/app/permissions.go` (`declareOrgPermissions`); every use case on an organisation's data calls `orgs.RequireMember(ctx, memberships, catalog, orgID, permission)` first |
| Organisation, member or invitation rule | `internal/modules/orgs/` |
| Send an email | Call the `mail.Sender` built as `mailer` in `internal/app/app.go` (pass it to the module); leave `From` empty so the `mail.*` settings apply |
| Email provider (Resend or SMTP) | `orb add mail --provider resend\|smtp --yes`; never edit `internal/app/infra_mail.go`, `internal/app/infra_mail_test.go` or the `# orb:begin mail` block by hand; other tests use the provider fixtures in `infra_mail_test.go`. Secrets go in `.env` only |
| Email sender name, address, reply-to | Runtime settings `mail.from_name`, `mail.from_email`, `mail.reply_to` (not env vars) |
| New module | `internal/modules/<module>/`, `internal/app/module_<module>.go`, one line in `internal/app/modules.go` |
| New resource that belongs to organisations (CRUD with its own table) | `orb gen resource <Name> <field:type>... --scope org --yes` (types `string`, `string:unique`, `text`, `'enum(a,b)'`), then `go run ./cmd/migrate`; it creates a module like `internal/modules/projects/`. It also adds the resource's permissions line after `//orb:anchor org-permissions` in `internal/app/permissions.go`. Keep the organisation ID in every query, `RequireMember` in every use case and the cross-organisation tests |

## Rules

- Keep `domain/` free of third-party imports and struct tags.
- Never read environment variables outside `internal/app`.
- Never import one module from another.
- Never read or change an organisation's data without `orgs.RequireMember` first, and never give platform roles access to it.
- Return domain errors from handlers; don't build HTTP errors in use cases.
- Request body structs start with ``_ struct{} `json:"-" additionalProperties:"true"` `` so unknown fields are ignored.
- Error codes, runtime setting keys and job names are public API: add new ones, never rename existing ones.
- Never put secrets in runtime settings or job arguments.
- Never log secrets, tokens, passwords or email addresses; log IDs.
- Never store passwords, session tokens, API keys or codes in plain text; use the auth library's `Hasher`, `NewToken`/`HashToken`, `NewAPIKey`/`APIKeyMatches` and `NewCode`/`HashCode`. Log an API key's lookup ID, never the key.
- Never send email directly through a provider; use the mailer so it's queued, retried and goes to Mailpit in development.
- Keep `//orb:anchor` comments; gorbital uses them to add modules and jobs.
